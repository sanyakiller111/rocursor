# Сборка и распространение

Документ отвечает на вопрос «как сделать .exe, которому не будут доверять
система и антивирусы». Это не паранойя — это самая частая причина, по которой
небольшая утилита не доходит до пользователя.

---

## 1. Решение: один onefile exe + установщик

Цель: запустил `build.bat` — и готовый `sanyakiller111.exe` лежит в корне
проекта. Поэтому PyInstaller собирает **onefile**: один файл, внутри
интерпретатор, Qt, Pillow и все ассеты (`assets/cursors`, `crosshairs`,
`skyboxes`, `icons`). При запуске он распаковывается во временный каталог
`sys._MEIPASS`; `content/cursor_library.py`, `crosshair.py` и `skybox.py`
ищут ассеты именно там.

| | onefile (как сейчас) | onedir |
|---|---|---|
| Что получает пользователь | один `.exe` | папку |
| Запуск | распаковка в `%TEMP%`, несколько секунд | сразу |
| Антивирус | эвристики дроппера могут срабатывать | обычное поведение |

Цена onefile — медленнее первый старт и более пристальное внимание
антивирусов (так ведёт себя самораспаковывающийся загрузчик). Смягчает это
подпись Authenticode (§3) и установщик Inno Setup: он кладёт тот же exe в
`%LOCALAPPDATA%\Programs\sanyakiller111` и регистрирует ассоциацию `.rcur`.
Если срабатывания станут проблемой, возврат к onedir — правка
`build/cursor_manager.spec` (добавить `COLLECT`, `exclude_binaries=True`).

**Nuitka не решает проблему:** его `--onefile` использует тот же
self-extracting загрузчик.

## 2. Что делает `build/build.py`

```
1. make_assets        28 курсоров + иконка + манифест с SHA-256 (osu-*.png сохраняются)
                      (если tools/ нет, а assets/ есть — просто берутся
                      готовые; так работает сборка из source zip)
2. version resource   FileVersion / ProductName / Copyright в PE
3. PyInstaller        build/work/dist/sanyakiller111.exe (onefile);
                      промежуточные файлы — build/work/
4. копия в корень     <корень>/sanyakiller111.exe — ГОТОВЫЙ EXE
5. Inno Setup         dist/sanyakiller111-Setup-<ver>.exe — упаковывает
                      этот же exe. Обязателен: нет ISCC.exe — сборка падает
                      с понятной ошибкой, а не «молча пропускает installer»
6. source zip         dist/sanyakiller111-<ver>-src.zip — исходники
7. SHA256SUMS         по установщику и source zip (+ build.json, где есть
                      и хеш корневого exe)
```

`AppId` в `installer.iss` зафиксирован и совпадает с прежним (Cursor
Manager 1.5.x), поэтому новый установщик обновляет старую установку; старые
`sanyakiller111-cursor-manager.exe` и `_internal` он удаляет сам.
Подпись Authenticode, если появится, встанет между шагами 3 и 5: Inno
встраивает файл при компиляции, поэтому подписывать exe нужно до установщика
(см. §3).

### Запуск

```bash
build.bat                        # канонично из корня
python build/build.py            # то же без bat-обёртки
python build/build.py --skip-assets   # не перерисовывать курсоры
```

`build.bat` переходит в корень проекта, берёт `.venv\Scripts\python.exe`
(иначе системный `python`), выставляет `PYTHONIOENCODING=utf-8` и запускает
`build\build.py` с переданными аргументами. В конце печатает полный путь
к готовому exe. Без аргументов (двойной клик) делает `pause`; с аргументами возвращает exit code сборщика.
В файле только ASCII — cmd.exe парсит .bat в OEM-кодировке, BOM ломает.

Флаги сборки, влияющие на антивирус, зашиты в `build/cursor_manager.spec`:
`upx=False` (UPX триггерит эвристику, экономия 3 МБ не окупает карантин),
`console=False`.

Размеры (exe, установщик, source zip) печатает сам build.py и пишет в
`dist/build.json`.

### Состав source zip

В архив входят `src/`, `assets/`, `build/`, `tests/`, `docs/` и файлы корня
(`README.md`, `LICENSE`, `pyproject.toml`,
`requirements-build.txt`, `build.bat`, `.gitignore`). Исключены `.venv/`,
`dist/`, `build/work/`, `__pycache__/`, `*.pyc`, логи и временные файлы.

`tools/` в архив не входят: регенерация ассетов — dev-сценарий,
а сгенерированные курсоры уже лежат в `assets/`. Поэтому сборка из
распакованного архива работает «как есть»: `make_assets()` видит, что
`tools/` нет, и не запускает регенерацию. Понадобился только Python с
`requirements-build.txt` и Inno Setup из §2.

## 3. Подпись Authenticode

### Какой сертификат

**Стандартный OV.** Не EV.

Microsoft убрала мгновенную репутацию SmartScreen для EV-сертификатов в 2024
году: и EV, и OV теперь набирают репутацию одинаково, через историю загрузок.
Платить за EV вдвое больше за то же самое смысла нет.

| | OV (стандартный) | EV |
|---|---|---|
| Цена | ~$215–400/год, Certum от ~$99 | ~$280–690/год |
| Кто может | физлицо с удостоверением | только организация |
| SmartScreen | через репутацию | через репутацию |
| Нужен для | этого приложения | только kernel-драйверы |

**Важно:** с 1 июня 2023 приватный ключ обязан лежать на оборудовании,
сертифицированном по FIPS 140-2 Level 2 или CC EAL 4+. Скачиваемого `.pfx`
для публично доверенного сертификата больше не существует. Варианты:

- **USB-токен** — подходит для ручной сборки релиза, ключ втыкается в машину
- **Облачная подпись** — Certum SimplySign и подобные: TOTP с телефона,
  два часа окна на подпись любого числа файлов. Это вариант для CI

`build.py` поддерживает оба:

```powershell
# локально, для разработки — самоподписанный .pfx
$env:SIGN_PFX = "dev-signing.pfx"
$env:SIGN_PFX_PASSWORD = "..."
python build/build.py --sign

# в CI — облачная подпись
$env:SIGN_CLOUD_CMD = "sign-cloud.bat"
# sign-cloud.bat: signtool sign /fd sha256 /tr http://timestamp.digicert.com /td sha256 "%1"
python build/build.py --sign
```

Без сертификата сборка тоже работает — просто остаётся без подписи.
Сейчас так и есть: `--sign` в `build/build.py` — заглушка, серт не настроен,
установщик неподписанный; SmartScreen при первом запуске может
предупреждать, репутация набирается скачиваниями.

### Что ещё помогает SmartScreen

Подпись убирает «Unknown Publisher», но не отключает SmartScreen — это
облачная репутация по хешу файла. Она набирается сама, когда люди скачивают
и запускают релиз. Ускоряется:

- одна и та же личность подписи на всех релизах (ротация сертификата
  обнуляет репутацию)
- верифицированный издатель в подписи
- `FileVersion` в ресурсе версии — системы репутации читают его отдельно;
  бинарник без него выглядит как «скрипт, который кто-то забыл подписать»
- загрузка релизов через браузер, а не через скрипт-загрузчик

Ручная отправка на ревью SmartScreen для пользовательских endpoint не
предусмотрена — это закрытая система.

## 4. Автоматическая сборка

`.github/workflows/build.yml` собирает на `windows-latest`, ставит Inno
Setup (обязательный шаг: нет `ISCC.exe` — сборка падает), гоняет тесты,
считает SHA-256 и отправляет артефакты в VirusTotal. Токен
`VIRUSTOTAL_API_KEY` в секретах репозитория — без него шаг пропускается,
сборка не падает.

Побайтовое воспроизведение локальной сборки требует тех же версий
Python, PyInstaller и Pillow — они зафиксированы в `requirements-build.txt`.

## 5. Распространение каталога курсоров

Отдельная система от распространения приложения. Манифест лежит по URL из
`version.CATALOG_URL` и имеет ту же схему проверки целостности: SHA-256
каждого файла, fail-closed.

Права на содержимое каталога — отдельный вопрос от прав на код приложения.
Свои 28 курсоров созданы этим репозиторием и распространяются под CC0. Курсоры osu! (`osu-*.png`) скачаны с osuskinner.com, права у их авторов.
Если в каталог попадает чужой арт, на него распространяются права автора,
а не лицензия приложения.

## 6. Порядок выпуска релиза

```
1. версия в src/cursor_manager/version.py
2. build.bat                        # или python build/build.py
3. загрузить установщик <slug>-Setup-<ver>.exe (основной артефакт),
   <slug>-<ver>-src.zip, SHA256SUMS, build.json в GitHub Release
4. отправить установщик в VirusTotal, дождаться отчёта, вставить ссылку
5. залить манифест каталога (tools/publish_catalog.py)
6. тег vX.Y.Z
```

Когда появится сертификат, между шагами 2 и 3 встанет подпись: `.exe`
подписывается до Inno Setup, установщик — после (см. §3); `--sign` в
сборщике уже оставлен под это.
